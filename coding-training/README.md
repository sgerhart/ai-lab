**Target:** `ai-lab/coding-training/`  
**Parent Project:** AI Lab (`ai-lab`)

**Status:** WO-00 Complete (Reconnaissance and ADRs delivered; Gate awaiting operator review)

---

## 1. Mission and Overview

The Execution-Verified Coding Model Training Platform is an educational and experimental subsystem inside AI Lab designed to measure and improve coding model capabilities through verifiable execution:

1. **Evaluation-Only:** Prompt a local model, execute candidate code against immutable test bundles in an isolated Linux VM, compute deterministic rewards, and generate comprehensive holdout benchmarks without weight updates.
2. **Verified SFT:** Mine passing candidate executions across training tasks, construct verified instruction/completion pairs, train LoRA/QLoRA adapters on the Mac Studio using MLX-LM, and evaluate on held-out tasks.
3. **Execution-Reward RL (Conditional):** Qualify on-policy Apple Silicon policy-gradient backends (GRPO family), perform grouped rollouts with live sandbox execution rewards, update adapter parameters, and verify generalization on held-out tasks.

## 2. Mandatory Safety Defaults

Per AI Lab safety defaults and the specification:

```ini
EXECUTION_ENABLED=false          # Refuses execution until sandbox security gate passes
TRAINING_ENABLED=false           # Refuses training until baseline + preflight approval
RL_ENABLED=false                 # Disabled until backend compatibility spike qualifies
SANDBOX_NETWORK_POLICY=deny_all  # Sandbox VM has zero network egress (including DNS)
MODEL_DOWNLOADS_ENABLED=false    # No automatic weight downloads
MAX_EXECUTION_PARALLELISM=1      # Conservative single-worker pilot
MAX_GENERATIONS_PER_TASK=4       # Initial generation limit
DEFAULT_REWARD_VERSION=reward-v1
```

**Cardinal Safety Invariants:**
- **No host execution:** Candidate code generated by models is NEVER executed on `mac-studio`, `mac-mini`, or `mac-air`. Execution occurs strictly within an attested, disposable sandbox on the isolated Security Compute Linux VM.
- **Distinct failure classes:** Infrastructure failures (worker timeouts, bad bundles, runner crashes) are strictly distinct from candidate test failures. Infrastructure failures are marked `unscorable` and NEVER assigned a reward of zero.
- **Hidden tests remain hidden:** Hidden unit tests are never leaked into model prompts, chat responses, or training datasets.
- **No fake RL:** An iterative prompt loop or test score does not constitute model training. Real training requires measured parameter updates, checksum changes, and verifiable checkpoints.
